# Fraud Pattern  
Phishing fraud involves deceptive tactics to extract sensitive information, often leveraging machine learning (ML) and natural language processing (NLP) for detection. The paper explores adaptive ML techniques, such as **Transfer Learning (TL)** and **Continual Learning (CL)**, to address challenges like **catastrophic forgetting** while improving phishing detection accuracy across evolving datasets.  

# Executive Summary  
This research evaluates **TL** and **CL** (specifically **Learning Without Forgetting (LWF)** and **Elastic Weight Consolidation (EWC)**) for phishing detection in dynamic environments. While **TL** excels in adapting to new tasks, it suffers from catastrophic forgetting. **CL** techniques retain historical knowledge, making them critical for long-term phishing detection. The paper also reviews ML/NLP methods for phishing, emphasizing **feature-based models**, **hybrid ensembles**, and **domain adaptation**.  

# Definition  
- **Phishing Fraud**: Deceptive tactics (e.g., fake emails, websites) to steal sensitive data.  
- **Transfer Learning (TL)**: Fine-tunes pre-trained models on new tasks without retraining from scratch.  
- **Continual Learning (CL)**: Learns new tasks while retaining performance on older ones (e.g., **LWF**, **EWC**).  
- **Catastrophic Forgetting**: Performance degradation on older tasks during model retraining.  

# Typical Attack Workflow  
Phishing attacks typically involve:  
1. Crafting deceptive emails/websites with malicious links.  
2. Exploiting user trust to extract credentials or financial data.  
3. Evolving tactics over time (e.g., 2018A → 2020B datasets).  

# Behavioural Characteristics  
- **Model Adaptation**:  
  - **TL**: Rapid adaptation to new datasets but poor retention of prior knowledge.  
  - **CL (LWF/EWC)**: Maintains performance across sequential datasets via regularization (e.g., **shared weights**, **gradient constraints**).  
- **Phishing Tactics**:  
  - Use of suspicious URLs, HTML features, and social engineering.  
  - Evolving patterns over time (e.g., domain variations, phishing kits).  

# Indicators  
- **Phishing Indicators**:  
  - Suspicious URLs, HTML anomalies, and NLP-based text features (e.g., urgency, typos).  
- **Model Performance**:  
  - **TL**: High accuracy on new tasks but significant accuracy drop on older datasets.  
  - **CL**: Stable accuracy across all datasets, though with higher computational overhead.  

# Common Feature Patterns  
- **Phishing Detection**:  
  - URL structure, image analysis, and linguistic patterns (e.g., keyword stuffing).  
- **Model Adaptation**:  
  - **LWF**: Shared weights between tasks.  
  - **EWC**: Fisher information matrix for gradient constraints.  

# Detection Signals  
- **Phishing**: NLP features (e.g., sentiment analysis, entity extraction), domain reputation checks.  
- **Model Adaptation**: Accuracy metrics, gradient divergence, and memory usage during retraining.  

# False Positives  
- **Phishing**: Legitimate emails/links misclassified due to feature overlap (e.g., marketing emails mimicking phishing).  
- **Model Adaptation**: Over-regularization in **CL** may reduce sensitivity to novel tasks.  

# Prevention  
- **Phishing**: Deploy hybrid ML models (e.g., **feature-based ensembles**) with real-time updates via **CL**.  
- **Model Adaptation**: Use **EWC** or **LWF** to balance retention and adaptation, reducing catastrophic forgetting.

# Fraud Pattern  
Account Takeover (ATO) fraud involves unauthorized access to user accounts, typically through compromised credentials or session hijacking. ATLAS, a spatio-temporal graph framework, addresses ATO detection by constructing a **time-respecting directed session graph** with edges representing user interactions (e.g., login attempts) and nodes representing sessions. Connectivity is regulated by a **time window (T)** (e.g., 1–120 days) and **recency cap (K)** (e.g., 1–10 recent sessions).  

# Executive Summary  
ATLAS introduces a scalable, real-time ATO detection framework leveraging **time-respecting directed session graphs** and **label propagation**. It outperforms XGBoost by **+5.8% in ROC AUC** (84.46%) through inductive GraphSAGE variants and serve-time-consistent label aggregation. Key innovations include temporal DAG constraints, neighbor sampling for scalability, and integration of enterprise-level latency requirements.  

# Definition  
Account Takeover (ATO) fraud refers to the unauthorized acquisition of user credentials or session control, enabling attackers to impersonate legitimate users for malicious purposes (e.g., financial theft, data exfiltration).  

# Typical Attack Workflow  
1. **Credential Compromise**: Attackers obtain user credentials via phishing, data breaches, or malware.  
2. **Session Hijacking**: Exploit weak session management or stolen tokens to take over active sessions.  
3. **Coordinated Attacks**: Use multiple compromised accounts or sessions to bypass detection thresholds (e.g., rate limiting).  

# Behavioural Characteristics  
- **Anomalous Login Patterns**: Unusual geographic locations, device fingerprints, or IP addresses.  
- **High Session Frequency**: Rapid succession of login attempts or session switches within a short time window (T).  
- **Latency Discrepancies**: Delays in user responses or interactions inconsistent with typical behavior.  

# Indicators  
- **Graph Anomalies**: Unusual clustering or connectivity patterns in session graphs (e.g., high-degree nodes).  
- **Temporal Irregularities**: Logins outside normal user activity hours or inconsistent session durations.  
- **Credential Reuse**: Multiple accounts sharing the same password or authentication token.  

# Common Feature Patterns  
- **Time Window Violations**: Sessions exceeding the time window (T) or recency cap (K) thresholds.  
- **Device/IP Mismatch**: Inconsistencies between user devices/IP addresses and historical records.  
- **Behavioral Deviations**: Uncharacteristic actions (e.g., bulk transactions, account modifications) during sessions.  

# Detection Signals  
- **Graph-Based Alerts**: Abnormal session graph structures (e.g., high clustering coefficients, disconnected subgraphs).  
- **Temporal Threshold Breaches**: Login attempts within the time window (T) or recency cap (K) that trigger anomaly scores.  
- **Behavioral Flags**: Use of suspicious devices/IPs or deviations from user-defined activity patterns.  

# False Positives  
- **Legitimate Multi-Device Usage**: Users accessing accounts from multiple trusted devices/IPs.  
- **Time Zone Shifts**: Legitimate travel or work schedules causing temporary deviations from normal activity patterns.  
- **System-Induced Delays**: Network latency or server-side delays misinterpreted as behavioral anomalies.  

# Prevention  
- **Multi-Factor Authentication (MFA)**: Enforce MFA to mitigate credential compromise.  
- **Session Monitoring**: Real-time detection of suspicious session activity (e.g., rapid login switches).  
- **Graph-Based Throttling**: Use session graph anomalies to dynamically adjust account access thresholds.
